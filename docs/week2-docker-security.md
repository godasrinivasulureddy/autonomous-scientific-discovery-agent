## 1. Overview and Objectives

In scientific discovery and automated hypothesis evaluation, code generated by AI agents must never run with unconstrained host privileges. The Docker sandbox provides a sealed, resource-bounded execution environment specifically designed to execute controlled Python statistical experiments and analysis scripts.

Key objectives achieved during Week 2:
1. **Dynamic Executable Discovery**: Resilient detection of the host Docker runtime using standard path inspection (shutil.which).
2. **Hardened Container Security**: Dropped Linux capabilities, read-only root filesystems, user namespace isolation, and strict network isolation.
3. **Deterministic Resource Bounds**: Strict caps on memory, CPU share, and maximum process/thread counts.
4. **Structured Execution Interface**: End-to-end integration with the CodeExecutor agent and reward feedback pipelines.

## 2. Security Restrictions and Configuration

Every container spawned via services.docker_sandbox.run_in_sandbox() runs under the following parameters:

- **--network none**: Blocks all outbound and inbound socket connections (prevents data exfiltration).
- **--read-only**: Container filesystem is immutable; prevents scripts from writing to root.
- **--cap-drop ALL**: Drops all Linux capabilities.
- **--security-opt no-new-privileges**: Prevents privilege escalation through setuid or setgid binaries.
- **--memory 128m**: Caps RAM allocation to 128 MB.
- **--memory-swap 128m**: Disables swap expansion beyond memory limit.
- **--cpus 0.5**: Allocates at most 50 percent of a single CPU core.
- **--pids-limit 64**: Prevents fork bombs and unbounded process creation.
- **--user 10001:10001**: Runs as unprivileged non-root user sandboxuser.
- **--tmpfs /tmp:rw,noexec,nosuid,size=16m**: Ephemeral in-memory storage, non-executable.

## 3. Code Executor and Workflow Integration

The Code Executor agent (agents/code_executor.py) interfaces with the Docker sandbox through execute_experiment_in_docker():

1. **Input Validation**: Input lists are strictly checked to ensure only finite numeric values (no boolean or arbitrary types) are accepted.
2. **Safe Serialization**: Inputs are converted to a serialized JSON string rather than executing unvalidated user strings.
3. **Structured Output**: Execution status, standard output, standard error, and calculated statistics (mean, standard_deviation, sample_size) are returned in a clean dictionary.
4. **Automatic Cleanup**: Containers that exceed timeouts (default 10s, max 30s) are force-removed with docker rm -f.
